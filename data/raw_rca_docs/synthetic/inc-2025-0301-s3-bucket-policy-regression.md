## Summary

A routine Terraform change intended to tighten public access on the `reports-export-prod` S3
bucket instead dropped the statement granting the CloudFront Origin Access Identity (OAI) read
access, causing every asset request through distribution `E1A2B3C4D5E6F7`
(`d2x9k1m4qz8vwe.cloudfront.net`) to fail with `403 Forbidden` and the S3 error body
`<Code>AccessDenied</Code><Message>Access Denied</Message>` for 26 minutes. The regression shipped
in PR #4821, which replaced a hand-maintained bucket policy JSON document with a
Terraform-generated one, and an incorrect merge silently dropped the pre-existing
`AllowCloudFrontOAI` statement instead of appending to it.

## Root Cause

PR #4821 replaced a hand-written, multi-statement bucket policy JSON file with one generated by
Terraform's `aws_iam_policy_document` data source, merging a new "deny public read" statement with
the existing OAI-read statement via `source_policy_documents`. The merge referenced the wrong
variable - a stale `data "aws_s3_bucket_policy"` lookup rather than the checked-in JSON file that
actually held the `AllowCloudFrontOAI` statement - so the generated document silently omitted that
statement entirely; `aws_iam_policy_document` does not error on an empty or stale merge source, it
simply produces fewer statements. Terraform's plan output showed "1 to change" with a full JSON
diff, which the reviewer approved without diffing statement-by-statement; the removed statement
was not visually obvious in the wall of JSON. Once applied, S3 found no `Allow` statement covering
the CloudFront OAI principal for `s3:GetObject` on `arn:aws:s3:::reports-export-prod/*` and
defaulted to implicit deny, returning `403 Forbidden` to every request CloudFront forwarded to the
origin regardless of the end user's own permissions.

## Impact

- Duration: 26 minutes of complete failure (06:40-07:06 UTC) for all downloads via distribution
  `E1A2B3C4D5E6F7`.
- 100% of requests to `d2x9k1m4qz8vwe.cloudfront.net` for `reports-export-prod` objects returned
  `403 Forbidden`; ~3,900 requests failed per CloudFront access logs.
- `client-portal`'s "Download Report" feature was fully unavailable; 41 support tickets were
  opened during the window.
- No data was lost or exposed; the regression was over-restrictive, not under-restrictive, so
  impact was availability only.

## Detection

Detected via CloudWatch alarm `cloudfront-reports-dist-5xxErrorRate-High`, triggering when
`5xxErrorRate` for distribution `E1A2B3C4D5E6F7` exceeds 5% over 3 consecutive 1-minute periods.
It fired 8 minutes after the Terraform apply completed, matching the time for cache-miss requests
to hit the new policy at scale. Acknowledgment took 3 minutes.

## Resolution

1. On-call reproduced the failure directly against the S3 origin (bypassing CloudFront) to confirm
   the fault was the bucket policy, not the CDN configuration.
2. Used `terraform state show` to inspect the applied policy and diff it against the pre-merge
   version in git history, identifying the missing `AllowCloudFrontOAI` statement.
3. Declared SEV-1 and rolled back via a targeted `terraform apply -target=` against the bucket
   policy resource, restoring the previous document rather than attempting a forward-fix.
4. Confirmed recovery via direct S3 `HEAD` requests and CloudFront-fronted requests across sampled
   edge locations before closing the incident.
5. Reverted PR #4821 in git and reopened the access-tightening work as a new PR requiring an
   explicit statement-level diff.

## Action Items

- Add a Terraform `plan` CI check that fails the build if a bucket-policy change removes any
  `Allow` statement whose principal matches a known CloudFront OAI/OAC, unless explicitly
  acknowledged in the PR. Owner: Platform Engineering. Ticket: SRE-8410.
- Require statement-by-statement policy diffs in the PR template for changes touching
  `aws_s3_bucket_policy` or `aws_iam_policy_document` resources. Owner: Platform Engineering.
  Ticket: SRE-8411.
- Migrate `reports-export-prod` from OAI to Origin Access Control (OAC) and add a synthetic canary
  requesting a known object every 2 minutes, alarming directly on `403`/`AccessDenied` rather than
  only aggregate 5xx rate. Owner: SRE team. Ticket: SRE-8412.
- Audit other CloudFront-fronted S3 buckets for policies generated via `aws_iam_policy_document`
  merges for the same silent-drop failure mode. Owner: Platform Engineering. Ticket: SRE-8413.
